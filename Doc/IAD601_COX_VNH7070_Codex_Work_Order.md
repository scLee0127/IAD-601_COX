# IAD-601 COX 펌웨어 수정 작업지시서

개정 범위는 VNH7070 모터 구동 이관, 실기에서 확인한 조작키·설정 메뉴·USART2 부팅 배너 증상, 확정된 GPIO 및 USART1 초기화 정합화다.

기준 소스는 IAD-601_COX_20261107.zip과 첨부 ELF·MAP이다. 첨부 회로 이미지는 기존 이산 소자 H-브리지 회로다. 신규 회로의 핀 기능은 사용자 확인과 IAD601_COX.ioc를 기준으로 하며, 실제 납땜된 부품과 네트는 보드 리비전별 회로도로 대조한다.

## 1. 목표 및 범위

- 기존 두 PWM·두 GND 제어를 VNH7070의 단일 PWM·INA/INB·SEL0 방식으로 이관한다.
- MYMOTOR_Init(), MYMOTOR_Proc(), MYMOTOR_Get_Motor_Pwm(), 기존 리미트 조회 API를 유지한다. 차압 PID, 데드밴드, 램프 설정, 기동·해제 판단, 20ms 제어 주기와 기존 100ms 반전 대기는 그대로 사용한다. 모터 옵션 저장 형식·값, 차압 제어와 릴레이 동작 정책을 보존한다. 키와 GUI는 6절, USART2 배너는 7절, GPIO와 USART1 초기화는 8절에 정의된 범위에서 별도 변경 묶음으로 처리한다.
- 기본 BOARD_MOTOR_ENABLE=0 빌드를 유지하고, 검증용으로만 활성 빌드를 별도 구성한다. 신규 회로 검증 정보가 부족한 항목은 미확정으로 기록한다. 해당 항목이 구동이나 보호에 영향을 주면 실제 모터를 통전하는 단계 전에 해결한다.

## 3. 저수준 구현 계약

### 핀과 출력 소유권

| MCU 핀 | 기능 | 구현 |
|---|---|---|
| PB14 | INA | GPIO 출력 |
| PB12 | INB | GPIO 출력 |
| PB15 | SEL0 | GPIO 출력. CS 채널·진단 선택 정책은 회로 확인 후 반영 |
| PB13 | PWM | TIM1_CH1N, AF2, 보완 채널 출력 |
| PF6 / PF7 | M_SW2 / M_SW1 | 각각 GPIO 입력. 풀업·극성·물리 열림/닫힘 매핑은 보드 확인값 적용 |

1. 모터 출력의 단일 소유자를 둔다. 기존 mygpio/mytimer에 작은 내부 경계를 두고, 상태 머신은 논리 방향과 듀티를 한 쌍으로 전달한다. 호출 형태는 예를 들어 MotorHw_Apply(dir, duty)와 MotorHw_Stop()이다. 이름은 프로젝트 관례에 맞춰도 된다. 상위 경로에서 INA, INB, SEL0 또는 CCR을 직접 쓰는 경로를 만들지 않는다.
2. GPIO 출력 래치에 정지 레벨을 먼저 기록하고 출력 모드로 전환한다. PB13은 타이머와 채널의 안전 상태를 준비한 뒤 AF로 넘긴다. TIM1 클록, CH1N enable, MOE, 보완 극성, idle/off-state, CCR preload를 함께 검토한다. STM32 HAL의 CH1N 시작 경로를 사용한다. 초기화 전·실패·0% 명령에서 물리적 PWM 입력이 LOW인지 확인하며, MCU가 구동할 수 없는 전원 인가·리셋 구간의 레벨은 보드 풀다운 등 회로 조건으로 검증한다.
3. 구동 요청에서 정·역방향은 INA/INB=10 또는 01로 구분한다. 어느 조합이 OPEN인지는 OUTA/OUTB 배선과 실제 동작으로 확정한다. 기존 NO/NC 옵션의 논리 의미를 유지하고, 방향 반전과 리미트 매핑에 옵션을 중복 적용하지 않는다. 기본 정지는 PWM LOW 후 INA/INB/SEL0를 LOW로 만드는 무구동 상태로 정의한다. 기존 _mymotor_break_stop()은 보호 경로에서 즉시 무구동으로 연결하고, 능동 브레이크는 요구와 검증 조건이 별도로 확정될 때 구현한다. 브레이크 중 전류와 정지 거리는 기존 회로와 다를 수 있다.
4. VNH7070BAS가 대기 상태일 수 있으면 제어 입력을 먼저 설정하고 ST가 제시한 20µs 대기 후 PWM을 허용한다. 반복 호출에서도 시퀀스가 한 번만 진행되도록 한다. 기존 2ms 스케줄러에서 실제 경과 시간으로 보장할 수 있으면 사용한다. 한 번의 메인 루프에서 실행되는 누적 호출 횟수는 대기 시간으로 세지 않는다. 반전은 기존 감속·100ms 대기를 거치고, PWM이 실제 LOW가 된 후 방향을 바꾼다. 대기 중 리미트·고장·정지 요청이 들어오면 예약된 출력을 취소한다.
5. 48MHz, 에지 정렬, PSC=0, ARR=2399일 때 20kHz이다. 이 값은 첨부 .ioc를 기준으로 한 검증 후보이며 VNH7070BAS 명시 상한이다. 0%, 중간 듀티, 상한 듀티에서 PB13의 실제 활성 시간과 주파수를 확인한다. 기존 최소 듀티·램프 설정을 초기 시험부터 자동 조정하지 않는다.
6. 전류 경로가 기존 외부 센서면 센서 전원·오프셋·감도를 대조해 기존 환산값의 사용 근거를 남긴다. CS 직결 또는 저항 변환이라면 INA/INB별 SEL0 선택, PA6 입력 범위, 센스 저항·보정, PWM ON 구간의 유효 샘플, 고장 레벨과 전류값의 구분을 확인한다. CS의 Hi-Z나 오래된 값을 정상 0A로 취급하지 않는다. 전류 보호 입력의 유효성과 임계값 해석을 검증하기 전에는 모터 통전 승인을 완료로 처리하지 않는다.

## 4. 허용하는 상위 변경

- _mymotor_shtter_state_update()의 기존 IDLE/RUN/SWITCH_PAUSE 계산은 유지한다. 각 경로에서 이전 방향을 끄는 명령과 현재 듀티 명령을 따로 발행하던 부분만 최종 출력 1회로 정리한다. 표시용 PWM API와 보호 로직에는 실제 적용 듀티·방향을 일관되게 제공한다. 기동 대기 중 적용 듀티는 0이다.
- MYMOTOR_Proc()의 리미트 검사는 구동 중 실제 적용 방향을 보고, 새 구동 허용 직전에는 요청 방향을 다시 검사한다. 해당 끝 위치를 향한 구동을 차단하고 반대 방향 이탈은 허용한다. 두 리미트 동시 활성은 구동을 막는다. 과전류·리미트 차단은 로그 출력 전에 처리하고, 듀티·방향·예약된 펄스를 정합적으로 정리한다. IWDG 리셋 후 재기동과 기존 과전류 해제 동작은 별도로 확인한다.
- 환경 옵션 적용 경로는 하드웨어 초기화와 분리한다. 운전 중 설정 적용이 과전류 래치를 해제하거나 이전 출력 명령을 다시 적용하는 경로를 차단한다. 기존 SEL 해제 경로는 유지한다. 변경이 필요한 경우 실제 부팅 초기화와 런타임 재적용의 역할만 분리한다.
- 화재 해제 복귀, 2ms 상태 갱신과 20ms PID, 기존 게인·램프·펄스 설정을 기준선과 비교한다. 반전 및 출력 대기 중에만 필요한 최소 변경을 허용한다. 기존 펄스 타이머의 중복 감소 등 독립적인 발견 사항은 별도 기록한다. 구동을 막는 재현 사례가 있을 경우 원인과 필요한 최소 수정 범위를 보고한다.

## 5. STM32F030 자원 제약과 완료 조건

- Flash 64KiB, SRAM 8KiB. 첨부 ELF는 Flash 63,148B, SRAM 5,104B(힙·스택 최소 예약 포함)다. 마지막 설정 페이지 시작은 0x0800FC00이고, 그 전 프로그램 영역의 첨부 빌드 여유는 1,364B이다. 비교 시 동일 툴체인·프로파일의 전후 수치와 활성·비활성 수치를 각각 기록한다.
- 초기화 데이터의 Flash 로드 주소까지 포함해 프로그램 이미지의 끝이 0x0800FC00 이하인지 확인한다. 기존 저장 주소와 형식은 유지한다. 힙 할당, 큰 배열, 신규 부동소수점 로그, 주기 루프의 블로킹 지연을 피한다.
- 소스 검증은 구형 모터 PWM이 FND 핀을 재설정하지 않는지, 각 상태 전이에서 방향·듀티의 소유자가 하나인지, 초기 로드와 설정 저장 시 초기화 순서가 올바른지 확인한다. BOARD_MOTOR_ENABLE=0/1의 Debug/Release를 빌드하고 ELF·MAP과 증감을 남긴다. 첨부 ZIP에는 CMake가 참조하는 Drivers/가 빠져 있으므로, 검증 시 실제 저장소의 동일 HAL/CMSIS를 사용한다.
- 보드 검증은 모터 분리 상태에서 리셋·부팅·정지의 무펄스와 PB13의 주파수·극성, INA/INB/SEL0 시퀀스를 먼저 확인한다. 이어 시험 장치에서 방향, 양 끝 리미트와 이탈, 반전 대기, 보호 중 즉시 차단, 옵션 재적용, 기동·해제, FND 표시를 확인한다. 센서 회로에 맞는 정상·과전류 입력을 검증하고, 보호 정지 시 기구적 이동량을 확인한다.
- 작업 결과에 변경 파일·함수, 상위 변경 사유, 빌드 자원, 키 이벤트·UART 로그·모터 파형 및 실기 결과, 미확정 회로 항목을 구분해 보고한다. 새 회로의 IC 정확한 품번·PB13 PWM 네트·CS/PA6·PF6/PF7 매핑과 극성이 확인되지 않은 상태는 벤치 통전 전 검토 대기로 표시한다.

### 재현 및 수정 기준

1. 실기에서 키 세 개가 반응하지 않고 SEL 롱프레스로 설정 메뉴에 진입하지 못했다. 현재 소스에는 GPIO 초기화와 메뉴 전이 코드가 있다. 같은 핀 이름이 있다는 사실만으로 실기 원인을 확정하지 않는다. 먼저 플래시한 ELF의 식별 정보를 남기고, 부팅 표시 종료 후 PA4/PA0/PA15에서 미누름 HIGH·누름 LOW·해제 HIGH를 실측한다. MCU GPIO 원시값, 발생 이벤트, GUI 상태를 순서대로 확인한다. 배너 복구 전에는 디버거로 확인할 수 있다.
2. 현행 100ms 폴링은 두 샘플 사이의 짧은 클릭을 놓친다. 기존 MYBTN_Proc()를 GPIO와 타이머 스텁으로 실행해 20~70ms 동안 LOW인 UP 입력이 이벤트 없이 끝나는 것을 재현했다. SEL을 계속 LOW로 유지한 동일 시험에서는 첫 LOW 샘플 후 2,200ms에 롱프레스가 한 번 발생했다. 주석의 1.5초를 제품 사양으로 해석하지 않는다.
3. 키별로 안정 상태, 눌린 시각, 롱프레스 발행 여부만 관리한다. 예를 들어 10ms 샘플링과 20ms 안정화는 검증용 시작값이다. 롱프레스는 샘플 횟수 대신 실제 경과 시간으로 판정한다. 제품 승인값이 있으면 적용하고, 별도 값이 없으면 현재 동작에 가까운 약 2.2초를 호환 기준으로 사용한다. 짧은 클릭은 안정된 해제에서 한 번, 롱프레스는 누르는 동안 한 번만 발행한다. 롱프레스 해제에 짧은 클릭이 이어지지 않아야 한다. 주기 경로에서 문자열 로그로 디바운스를 지연시키지 않는다.
4. 대기 화면은 UP/DOWN 짧은 입력에 별도 화면 동작이 없을 수 있다. 원시 GPIO와 이벤트를 확인한 뒤 설정 메뉴 안에서 UP/DOWN 증감 및 SEL 선택을 검증한다. SEL 짧은 입력의 기존 과전류 해제는 해당 클릭이 실제로 발생한 경우에만 동작해야 한다. 기존 부팅 표시 중 입력 정책과 메뉴 타임아웃을 유지하고, 한 번의 누름을 중복 소비하는 별도 MYBTN_Proc() 호출을 만들지 않는다.
5. 완료 기준은 UP/DOWN/SEL 각 키의 50ms 단일 입력을 서로 다른 샘플 위상에서 한 번씩 인식하는 것, 접점 바운스에서 중복 이벤트가 없는 것, SEL 롱프레스 한 번으로 메뉴가 열리고 해제 시 추가 클릭이 없는 것, 메뉴에서 UP/DOWN/SEL의 기존 기능이 동작하는 것이다. 부팅 직후와 대기 화면에서 결과를 구분해 기록한다.

## 7. 실기 증상 B — USART2 부팅 배너 미출력

- 대상은 Core/Src/main.c의 main(), Print_Banner(), __io_putchar(), Core/Src/myuart.c의 MYUART_Debug_Init(), _myuart_uart2_debug_init(), Core/Src/stm32f0xx_hal_msp.c의 HAL_UART_MspInit(), Core/Src/syscalls.c의 _write()이다.
- 소스의 디버그 설정은 USART2, PA2 TX / PA3 RX, AF1, 230400bps 8N1, 흐름 제어 없음이다. 첨부 ELF에는 Print_Banner(), __io_putchar(), _write()가 링크되어 있다. 현재 배너는 USART2 초기화 직후가 아니라 옵션 읽기·출력과 RS-485·타이머·ADC 초기화 이후에 호출된다. 실기에서 배너만 없는지, USART2의 모든 출력이 없는지부터 구분한다.
- 리셋 전에 230400 8N1로 캡처를 시작하고 GND 및 디버그 커넥터의 TX→어댑터 RX 배선을 확인한다. PA2의 파형 유무와 비트 폭을 확인한다. 파형이 없으면 MYUART_Debug_Init() 진입, HAL_UART_Init() 결과, PA2 AF1과 USART2 클록, __io_putchar()의 전송 결과를 추적한다. 파형이 있는데 디코딩이 되지 않으면 보레이트와 MCU 클록을 먼저 대조한다. 다른 로그는 보이면 Print_Banner() 앞의 초기화에서 정체·리셋이 있는지 확인한다.
- USART2 초기화가 성공한 직후 초기 배너를 한 번 출력하도록 호출을 배치한다. 동일 배너를 나중에 다시 호출하는 경로를 정리하고, 보드별 배너 제품명 변경은 식별명이 확정된 경우만 적용한다. 출력 오류를 성공으로 기록하지 않도록 실제 전송 상태를 확인할 수 있게 한다. USART1이나 RS-485 방향핀을 디버그 출력에 연결하지 않는다.
- 완료 기준은 전원 인가와 리셋 각각에서 USART2에 배너가 한 번, 읽을 수 있는 형식으로 출력되는 것이다. 배너만 미출력 또는 전체 출력 미출력의 원인, 실측 설정, 최초 로그를 남긴다.

## 8. 확정된 핀 및 USART1 설정 정합화

| 항목 | 작업 지시 |
|---|---|
| PA11 외부 릴레이 | IAD601_COX.ioc에서 GPIO_Output으로 정정하고 실제 Push-Pull 초기화와 일치시킨다. 기존 PB11 연동과 활성 극성은 추가 사양 없이 변경하지 않는다. |
| PA12 기동 확인 | PA1 기동 입력에 따라 출력되는 현재 동작을 회귀 검증한다. 댐퍼 위치 조건을 추가하지 않는다. |
| PB7 FND_DP | .ioc와 main.h의 GND_DP 라벨을 FND_DP로 정합화하고, 기존 소수점 출력을 검증한다. |
| PB8/PB9 | 외부 풀업이 있는 소프트웨어 I²C 구성을 유지한다. .ioc와 CubeMX 재생성 정책을 정합화해 하드웨어 I²C 초기화가 GPIO 오픈드레인을 덮어쓰지 않도록 한다. |
| USART1 RS-485 | Core/Src/myuart.c의 _myuart_uart1_rs485_init(), MYUART_RS485_ReInit()에서 초기화 성공 후 RXNE·IDLE 및 USART1_IRQn을 일관되게 활성화한다. 재초기화 시 남은 플래그와 수신 상태를 정리하고, DMA1 Channel 2 및 PA8 수신 기본 상태를 검증한다. 프로토콜 활성화 여부는 기존 정책에 따른다. |
| VNH7070·PF6/PF7 | 2~5절의 이관 작업을 그대로 수행한다. 실기 목록의 ‘모터 구동’에는 별도 고장 양상이 명시되지 않았으므로 신규 드라이버 적용 및 구동 검증 항목으로 기록한다. |

## 9. 작업 순서와 결과 제출

1. 모터 비활성 기준 빌드로 USART2 배너와 키 증상을 각각 재현한다. 배너와 키 수정은 검증 결과를 따로 남긴다.
2. PA11·PB7·I²C 및 USART1 초기화 정합화를 독립 변경으로 검증한다. PA12의 기동 확인 출력은 기존 동작과 대조한다.
3. VNH7070 모터 활성 검증 빌드에서 모터를 분리한 상태로 PWM과 INA/INB/SEL0 파형, 리미트 입력을 확인한 뒤, 3절 및 5절의 통전 전 확인 항목을 충족하면 구동 검증을 수행한다.
4. 각 변경 묶음에 재현 조건, 변경 파일과 함수, 결과, 검증하지 못한 항목, Flash/SRAM 증감을 기록한다. 배너의 출력 순서, 키 롱프레스 시간, 모터의 무구동 정지와 같이 구현에서 결정한 동작은 별도로 명시한다.
